---
type: action
id: TACTION_DESTROY_TAG
title: Destroy Tag
summary: Removes every tag of the named type and takes the triggers riding on it with them.
valid_values:
  - A tag type the scenario declares. Each tag built from it is removed, including the private tag a team makes for itself from that type.
caveats:
  - The tag goes on the spot. Its triggers are queued instead and released at the end of the frame.
  - A queued trigger is not marked as dying while it waits, so Force Trigger can still fire one in the rest of that frame even though nothing is left to spring it.
  - A trigger that names the tag type carrying it releases the tag its own springing is walking, and the springing writes back into that released storage when it finishes.

## The disposal that clears a held victory

This is the one disposal that reliably gives an [allow-win](/mapping/actions/taction-allowwin/#destroying-the-tag-instead) blockage back. The triggers are still hanging off the tag when it goes, so the link the count is credited through is intact, whatever [lifetime](/systems/trigger-springing/#tag-lifetimes) the tag carried and however many triggers it held. That page owns the count and the two ways of losing it.

:::danger[Removing the last matching tag reads past the end of the list]
The number of tags is read once, before the loop that removes them, and each removal shortens the live list without shortening the loop. The passes left over read positions at or past the live end of the list, with no bounds test anywhere on the way, and the position they land on still holds the tag that was just released. Where that released storage still reads as the named type, the same tag is released a second time.
:::
