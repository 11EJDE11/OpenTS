title: Destroy Trigger
summary: Removes every trigger of the named type from the scenario for good.
valid_values:
  - A trigger type the scenario declares. One trigger is built from it for each tag that carries it, and every one of those is removed.
caveats:
  - The removal is immediate rather than queued, so it takes effect part way through the firing that asked for it.
  - A trigger that names its own type here releases the very trigger whose actions are running. Every action that follows on the same list carries on reading that released storage.
  - The tag survives. Only the triggers hanging off it are taken away.

## The tag is left behind

Each trigger unhooks itself from its tag as it goes, moving the tag's link on to the next trigger in the chain. A tag that carried a single trigger — the ordinary shape — is therefore left naming nothing at all. It stays on whatever it was riding on and springs nothing for the rest of the scenario.

That empty link is what costs a house its victory when the tag was an [allow-win](/mapping/actions/taction-allowwin/#destroying-the-tag-instead) tag: the link is where the disposal reads the house to credit, so destroying the triggers first and the tag afterwards gives nothing back.

:::danger[An emptied tag is read through when a variable changes]
Every change to a global or a local variable walks the whole tag list and follows each tag's link, so that timed events tied to that variable can be restarted. The link is followed without testing whether it is still there. Once this action has taken the last trigger off a tag, the next change to any global or local variable reads through an empty link.
:::

:::danger[Removing the last matching trigger reads past the end of the list]
The number of triggers is read once, before the loop that removes them, and each removal shortens the live list without shortening the loop. The passes left over read positions at or past the live end of the list, with no bounds test anywhere on the way, and the position they land on still holds the trigger that was just released. Where that released storage still reads as the named type, the same trigger is released a second time.
:::
